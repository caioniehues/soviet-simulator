`docs/superpowers/iterations/roadmap.md` is generated from `requirements/EPIC-*.md`
by `docs/superpowers/iterations/build_roadmap.py`. Verify any roadmap claim by
running the script from the repo root and diffing the output — a reviewer never
needs to trust the roadmap prose.

**Why:** the impacted-scenario sets are derived from AC `scenario:` tags, so hand
edits to roadmap.md are silently overwritten and drift is invisible otherwise.

**How to apply:**
- Story IDs are reassigned on every re-aggregation — match stories by TITLE, never by ID.
- The `OVERRIDE` dict is keyed by story TITLE. A typo/reword in a title makes the
  override silently no-op and the story falls back to its epic's iteration; the
  `assert` only fires when the EPIC theme is also unknown. Always cross-check each
  override key against the actual `**Title:**` line in requirements.
- Epic→iteration mapping is theme-level, so a rationale/look-ahead paragraph can
  describe stories that live in a different iteration (seen 2026-08-22: ITER-0013's
  rationale claimed vehicle manufacture / rail consists / scrapyard, all of which
  are EPIC-035 → ITER-0003).
- AC-loss check across a re-aggregation: extract `^- AC-\d+: ` bodies from
  `git show HEAD:<file>` vs the worktree and set-compare the first ~70 chars.

Ecosystem Research · soviet-simulator

2026-08-27 · 8 researcher agents · 6 lenses + vulkano/wgpu comparison + codebase scan

Synthesis

Stay on wgpu. Switching to vulkano would require rewriting 31 WGSL shaders, 13 render pipelines, and both UI integrations (yakui-wgpu, egui-wgpu) — for a library with an 18-month release gap, 15× fewer commits, and no WGSL support. The 250k-entity target is achievable on wgpu with GPU-driven culling (compute shader → multi_draw_indirect); Bevy 0.16 benchmarks 127k objects at 101 FPS using this pattern.

Most gaps are ours to build. No crate implements Kornai's shortage economy, freight custody state machines, BPR volume-delay, reservoir-graph water, or runtime dispatch loops. These are domain-specific — they are the game, not library work. The ecosystem provides noise generation, VRP solving, validation macros, and rendering patterns — components, not replacements.

Three things worth adopting: noise-rs or fastnoise-lite for terrain generation input; garde or validator for prototype struct range checks; and the GPU-culling pattern from vkguide/Bevy/Ambient for entity rendering at scale.

Our codebase: 29 files import wgpu (all in engine/src/), 31 WGSL shaders, 13 render pipelines, 1 compute pipeline, zero GLSL/SPIR-V. wgpu is walled behind GfxContext. UI depends on yakui-wgpu and egui-wgpu — no vulkano equivalents exist.

Migration cost to vulkano: full shader rewrite (WGSL→GLSL), pipeline rebuild, buffer management rewrite, swapchain rewrite, UI library replacement. Cost to upgrade wgpu 0.20→v30: 10 major versions of breaking changes, but WGSL shaders survive and migration notes exist for each.

Vulkano's theoretical advantage (multi-queue, bindless) does not justify the migration. wgpu's single-queue limitation has not been shown to be our bottleneck. The 250k target is a CPU-side culling problem, not a GPU-queue problem.

1 · Rendering at 250k entities

GPU-driven culling is the pattern

Study & port

Our entity_render.rs iterates all vehicles + humans every frame (humans twice). Three sibling modules already cull (frustum, bbox, circle) — entity_render does not. The fix is a compute shader that culls AABBs against the frustum and writes surviving instances into an indirect draw buffer.

No wgpu benchmark exists at exactly 250k entities. Closest data points: 250k on OpenGL (50 FPS, no culling), 250k on Vulkan (60+ FPS with GPU cull), 127k on wgpu (101 FPS with GPU cull). Extrapolation is favourable but unproven — a custom benchmark is required.

Palette rendering: No crate exists. The pattern is a WGSL fragment shader: grayscale texture index → palette array lookup. ~20 lines. Maps directly to our Lua color table.

Day/night: No standalone crate outside Bevy. The pattern is: time scalar (0–24h) → lerp sun direction → pass as uniform → multiply in fragment shader. ~20 lines.

3 · Shortage economy — Kornai model

No implementation exists in any language

Build from scratch

Searched GitHub repos, academic indices (arXiv), developer indices, and web. Zero open-source implementations of Kornai's shortage economy, dishonest enterprise, request-multiplier inflation, soft budget constraint, or queue-based clearing as a first-class economic system.

The bullwhip effect is the same mechanism as dishonest-enterprise request inflation, transposed to a different domain. The ordering policies (order-up-to with safety stock, smoothing variants) are the mathematical formulation of "how much to over-request." The amplification ratio is a tuning metric. The deepbullwhip codebase and Beer Game environment are the closest algorithmic references.

Also notable: SpaceProjectSim (Rust, 189★) has "shortage-urgency multipliers" that modulate pricing by scarcity level — adaptable to queue-priority adjustment. Worth a source-code read.

Unknown-key detection is the hard gap. No Rust crate solves it — it is a property of the source table, not the deserialized struct. Two paths: (A) extend the gen_prototypes! macro to emit a known-fields set, iterate Table::pairs() after from_lua(), warn on unrecognised keys — no external dependency. (B) Run a Lua-side validator (tableshape or osyrisrblx/t) before Rust reads the table — requires Luau compatibility testing.

Recommended path: Add garde derive macros to prototype structs for range checks. Extend the existing macro to emit a known-fields &[&str] and check Table::pairs() against it. No Lua-side dependency needed.

Explicit gaps — what we build ourselves

Shortage economy

Kornai model

No implementation in any language. Dishonest enterprise, request-multiplier inflation, soft budget constraint, queue-based clearing — all custom. Nearest algorithmic reference: bullwhip effect literature.

Freight custody

State machine

Factory→truck→store custody handoffs with haul events. No crate anywhere. Domain-specific game logic.

BPR & Gawron

Volume-delay + route blending

Zero Rust implementations. BPR formula is trivial (~5 lines); Frank-Wolfe equilibrium assignment is the real work. Design refs: eqasim (Java), AequilibraE (Python).

Reservoir-graph water

Persistent hydrology

No Rust crate. Closest: fastlem's drainage network (archived, MPL-2.0). Build from the Delaunay + flow-accumulation pattern.

Runtime dispatch

Continuous dispatcher

All VRP solvers are offline/batch. The event-driven dispatch loop that reacts to simulation state — including recovery on failed delivery — is game logic.

Determinism proof

At 250k scale

No crate publishes a repeat-run divergence test at 250k entities. The pattern (hash state per tick, compare on replay) is ~50 lines — our determinism test already has the structure, it just needs teeth.
